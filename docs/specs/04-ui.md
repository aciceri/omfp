# 04 — UI (TypeScript)

The UI is a TypeScript web app (D-18): React 19 with React Aria Components (S-11), styled by our own token CSS, built with
Bun. The same bundle runs in the browser, served by the daemon (DMN-008), and in the Tauri desktop window.

## Platforms

| | Web | Desktop |
| --- | --- | --- |
| Runtime | the release bundle in the browser | the same bundle in a Tauri 2 system webview (WebKitGTK on Linux, WKWebView on macOS) |
| Daemon | remote/local `omfp daemon`, which also serves the bundle | the data directory's local daemon, found or started by `omfp desktop` (ARC-003) |
| WebSocket client | `@omfp/client` over `WebSocket` | the same |
| Token | entered once, or from the URL fragment `#token=…`; kept in `localStorage` | read from the data directory by `omfp desktop` |

## State

| ID | Requirement |
| --- | --- |
| UI-010 | **Reducer state**: thread state MUST come only from the `omfp-core` reducer (ARC-006); UI-only state (scroll, expanded cards, drafts) lives beside it and is never sent to the daemon. |
| UI-011 | **Pure view models**: display logic (grouping, labels, badges, tool-card summaries, diff stats) MUST be pure functions testable without a DOM. |
| UI-012 | **Frame coalescing**: streaming model updates MUST be coalesced to at most one render per animation frame. |
| UI-335 | **Recent threads stay followed**: a `thread/<id>` topic MUST stay subscribed after no widget shows it, for the most recently hidden threads (UI-996; least recent released first, deleted threads released), unwatched (UI-997), so switching back sends no `subscribe` and renders at once. Any other topic re-followed in the same task it was released in (e.g. a hidden tab while another view of it shows, UI-390, UI-400) MUST stay subscribed without a `Loading…` flash; otherwise it is unsubscribed. |
| UI-996 | **How many threads a window keeps**: UI-335's bound MUST be `[ui] recent_threads` (0–100 or `"all"`, default 20; `:set recent_threads=<n>`, UI-097), applied live: lowering releases the oldest at once, `0` keeps none, `"all"` keeps every shown thread until close/reload. The cost is window memory (a 10,000-message thread ≈ 5.5 MB), which may kill a phone tab. |
| UI-997 | **Kept threads are not watched**: a kept thread (UI-335) MUST switch to `watch { topic, watch: false }` (PRT-223) on the same subscription, so it holds no omp (DMN-356, DMN-357) while the window still shows its transcript and stopped state; showing it again sends `watch: true` (no new snapshot); resubscriptions keep the flag (PRT-222). |
| UI-998 | **Showing a thread starts no omp**: showing, keeping or focusing a thread's composer MUST NOT start its omp (DMN-070); `thread.commands` is asked only once the draft starts with `/` (UI-060, DMN-358), and models of a stopped thread come from `auth.models` once per window and login state (UI-385, PRT-141). omp starts on a send, `/` command, model/thinking change, Restart, or an omp-only request (tree refresh, subagent transcript, Fork). |

| UI-625 | **Announced**: after the daemon answers, the live region MUST say `Moved <title> to position N of M in <workspace>`, `Moved <title> to <workspace>, position N of M` or `Moved workspace <name> to position N of M`; a refusal goes to the error toasts. |
