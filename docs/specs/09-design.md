# 09 — Visual design: Crush

The look of omfp, binding for the shell, the kit (`omfp/kit`, UI-093) and the `/kit` gallery. It refines UI-091
(tokens and themes), UI-094 (fonts and density) and UI-097 (`[ui]` settings); where they disagree on a default, this
document wins (D-20). The default skin is **Crush**, after Charm's terminal UI of the same name: monospace chrome with a
few box-drawing glyphs, bold accents, gradients built from the theme's own roles and motion as the identity, while long
reading stays in a serif face and every effect can be switched off. The opt-in **boring** skin is a calm, conventional
web app look ([Skins](#skins)).

## Principles

| ID | Requirement |
| --- | --- |
| UI-120 | omfp's own visual style is **Crush**, in our own CSS (D-10, D-20), with no CSS framework or component library styles. Crush is the default skin; the opt-in **boring** skin (UI-794..UI-797) restyles the same components, and every row here describes Crush unless a boring row overrides it. Themes change colors and fonts through tokens only (UI-091), never layout, glyphs or motion, and any theme works with either skin. |
| UI-121 | **Two families, two jobs.** Text read as text (message prose, Markdown, ask option descriptions, the composer's input) uses the prose family (serif); everything else (chrome, metadata, secondary text such as thinking, UI-338, and code) uses the code family (monospace). Crush has no third, sans-serif family: `--omfp-font-ui` is `--omfp-font-code`. |
| UI-122 | **Glyph vocabulary.** Glyphs are code-family text colored by tokens, never images: `◆` an identity or a call for attention (chat title, assistant name, approval and ask titles, mode-line notice, *awaiting*); `▸` the current choice or a closed disclosure (`▾` open); `●` a finished tool call; `○` an idle thread; braille spinners for running (UI-216); `╭─` a titled group (command menu, gallery sections); `·` separates mode-line segments and `@` prefixes the host. Lucide icons (UI-131) cover the rest. |
| UI-123 | **Gradients only where listed** (UI-135): the logo's `π`; gradient text on the chat title, the current workspace name, the assistant's name and gallery titles; fills of the primary button, the selected tab's indicator, the `INSERT` and `COMMAND` pills, the command-line prompt, the caret, progress, meters and the live spectrum; hairlines under the chat header and above the mode line; the insert-mode composer border; the selection background; the selected row's bar and the bars of UI-208. Anything else is flat. |
| UI-124 | **Motion is the identity, never a requirement.** Every animation is listed in the motion catalogue (UI-146) with the levels that keep it; at motion `none` (UI-145) the UI is fully static and loses no information: every animated state also has a static form (glyph, color or text). |

## Skins

A skin is the look of the whole UI on top of the tokens: Crush (the default) or **boring**. Boring is one more
stylesheet per stylesheet it overrides (the kit's, the app's and its built-in widgets'); it adds no kit API, no
component variant and no second kit.

| ID | Requirement |
| --- | --- |
| UI-794 | **The skin setting.** `[ui] skin` (UI-097, PRT-213) MUST be `crush` (absent: the default) or `boring`; `settings.set` and `:set skin=…` change it live in every window as `<html data-skin>`, independent of `data-theme`, `data-density` and `data-motion` and already in the served page so the first paint has it (UI-091). Widgets read and change it like the other settings. |
| UI-795 | **Boring's look**: a conventional web app, overriding Crush (under `:root[data-skin="boring"]`, tokens only) where it differs: the system sans-serif except for code; neutral gray hover, press, selection and focus tint; the accent only for focus, links, the selected tab, checks and progress; status colors as small marks; no gradients, `╭─` titles, `▸` or `◆` (dots instead) or `·` separators; a lowercase mode badge; light borders and soft shadows; the user's message in a bubble; no decorative motion. |
| UI-796 | **Glyphs in the stylesheets.** Crush's decorative glyphs (UI-122): disclosures `▸`/`▾`, box titles' `╭─`, the transcript names' `▸`/`◆` and spinner frames MUST come from CSS (`::before` content, keyframes), never from text in the kit's markup, so a skin can draw its own. |
| UI-797 | **Both skins in the gallery.** `/kit` (UI-173) MUST take `?skin=crush\|boring` and its header's picker links both skins next to the themes and schemes, keeping the other parameters; every gallery check (UI-174) runs in both skins. |
| UI-984 | **Boring focus on the composer.** In the boring skin a focused field (UI-150) draws a soft accent ring around its box, except the composer's text area (UI-172), which has no box: the composer box draws that ring on `:focus-within`, so the composer shows one focus indication. |

## Tokens

All design tokens live in one namespace, `--omfp-*`, next to the Material 3 color roles of UI-091, in the
`omfp-tokens` cascade layer, so a theme overrides any of them without `!important`. Their values are in
[tokens.css](../../ui/packages/kit/src/tokens.css) and on the `/kit` token sheet (UI-173); the rows fix names, roles
and relations.

| ID | Requirement |
| --- | --- |
| UI-125 | Every length, size, color, duration and easing in the shell or the kit MUST come from `--omfp-*` tokens (or a `color-mix()` / `calc()` of them); the only literals allowed in component CSS are `1px` / `2px` hairlines and strokes, `999px` pills, `50%` round marks and percentages inside `color-mix()`. |
| UI-126 | **Type scale.** `--omfp-fs-2xs`, `-xs`, `-sm`, `-md`, `-lg`, `-xl`, `-prose` and `-code` are in `rem` (UI-094), so `[ui] font_size` (default 17 px, UI-144) scales them, and do not change with density; weights are 400, 600 and 700 only (`--omfp-fw-regular`, `-medium`, `-strong`; the bundled faces have no 500, UI-141); line heights are `--omfp-lh-ui`, `-prose` and `-code`. |
| UI-127 | **Spacing.** The steps `--omfp-s1`…`--omfp-s6` and `--omfp-s8` are `--omfp-unit` × n × `--omfp-density` (`1` compact, the default; `1.3` normal; `[ui] density`, UI-097) and carry paddings, gaps and margins; text spacing tokens (key chips, counts, exit tags, inline code, Markdown flow, glyph gaps) are in `em` / `ch` and scale with their text instead; `--omfp-scrollbar-clearance` is a fixed lower bound for overlay scrollbars. |
| UI-128 | **Layout sizes**: row, control and message-gap heights (`--omfp-row-h`, `--omfp-ctl-h`, `--omfp-ctl-h-sm`, `--omfp-msg-gap`) scale with density; frame sizes (columns, bars, gutter, reading measure, touch target, floating panel, tooltip and toast widths) do not. |
| UI-129 | **Radii and borders.** Radii `--omfp-r-ctl` (controls), `--omfp-r-row` (rows, menu items), `--omfp-r-chip` (chips, badges, inline code) and `--omfp-r-card` (cards, popovers, dialogs, code blocks, composer), pills `999px`; borders `--omfp-bw`, rules `--omfp-rule` and `--omfp-rule-strong`. Borders are solid except the **dashed** ones, meaning pending or placeholder: approval and ask cards, queued and ghost chips, empty states, gallery size separators. Accent bars are 2 px solid. |
| UI-130 | **Surfaces and elevation.** Crush is flat: elevation is a surface role plus a primary-tinted border, not grey shadows. The app is on `surface`, the left column and mode line on `surface-container-lowest`, code on `surface-container-low`; cards, fields and controls are transparent on their parent. Popovers, menus, dialogs and toasts use `--omfp-pop-bg`, `--omfp-pop-border` and `--omfp-pop-shadow`, the only shadow in the UI; the modal scrim is `scrim` at 36 %. |
| UI-131 | **Icons** are Lucide, stroked with `currentColor` at `--omfp-ic-stroke`, sized `--omfp-ic` (state marks, toolbars) or `--omfp-ic-sm` (inside small controls, fields, rows, menus), smaller for inline metadata and larger for empty states. Where a glyph of UI-122 has the job (state marks, tool status, disclosure), no icon is shown. |
| UI-132 | **Focus** shows on `:focus-visible` only (fields: `:focus-within`), from the kit's shared classes (`omfp-focus-item` with `omfp-focus-item__target`, `omfp-focus-ring`, `omfp-focus-inset`). Items moved between (rows, tool cards, section and disclosure heads, transcript items, the notice) get the tint `--omfp-focus-bg` and a 2 px `--omfp-focus-bar` on their start edge, replacing a selected row's bar; controls and scroll regions a 1 px primary ring; text fields a primary border. Nothing moves or animates; forced colors use `Highlight`. |
| UI-133 | **Interactive states**, the same everywhere: hover `--omfp-hover` and pressed `--omfp-press` (primary tints; buttons also move down 1 px), selected `--omfp-sel-bg` (the soft gradient) with `--omfp-sel-fg`, disabled at `--omfp-disabled` opacity with a `not-allowed` cursor and no hover, invalid in `error`, busy a spinner beside the kept label. Transitions use `--omfp-dur-1` and `--omfp-ease`, larger changes `--omfp-dur-2`. |

## Color

| ID | Requirement |
| --- | --- |
| UI-134 | Every color is a Material 3 role token (UI-091), `--omfp-success` / `--omfp-warning`, or a `color-mix(in oklab, …)` of them; no literal color appears outside theme files. Roles keep their M3 meaning: `primary` the accent (actions, running, selection, insert mode), `tertiary` the second accent (the user's voice, command mode, inline code, key chips), `error` failures and destructive actions, `on-surface-variant` secondary text, `outline-variant` rules. |
| UI-135 | **Gradients** come from roles only: `--omfp-grad` runs primary → tertiary → `--omfp-grad-end` (tertiary pulled toward `on-surface`), `--omfp-grad-loop` is its animated form, `--omfp-grad-soft` a faint one for selection, and command mode reverses `--omfp-grad`. The end stop toward `on-surface` keeps a gradient visible and readable when a theme's primary and tertiary are close, so no theme defines gradient tokens; gradient text reaches 4.5:1 at every stop. |
| UI-136 | **Success and warning** have no M3 role: `--omfp-success` / `--omfp-warning` (and `on-` variants) are base tokens for light and dark that themes MAY override, used only as `--omfp-ok` / `--omfp-warn` (mixed into `surface`, so they take its tint); their light values reach 4.5:1 as text on `surface` up to `surface-container`. |
| UI-137 | **Status colors.** Running `primary`; awaiting the user `--omfp-warn`; failed `error`; unread `primary` with a bold title; idle `outline`. Approval and ask cards use `--omfp-warn`; finished tool calls `--omfp-ok` or `error`; the token meter turns `--omfp-warn` above its threshold; a dirty repo and modified files `--omfp-warn`, added `--omfp-ok`, deleted `error`; exit code 0 `--omfp-ok`, others `error`, each on its own tint. |
| UI-138 | **Diff, syntax and terminal colors.** Diff lines on `--omfp-ok` / `error` tints with text mixed toward `on-surface`, hunk headers `on-surface-variant`. Syntax: keywords `primary`, titles `tertiary`, strings `--omfp-ok`, numbers `--omfp-warn`, attributes and variables `secondary`, comments italic `on-surface-variant`, punctuation `outline`. ANSI: red `error`, green `--omfp-ok`, yellow `--omfp-warn`, blue `primary`, magenta `tertiary`, cyan between primary and ok, dim muted. Text selection is a primary tint. |
| UI-139 | **Built-in palette: Synth** (cyan → indigo), an M3 tonal-spot scheme and the default built-in theme (UI-510), in light and dark following `prefers-color-scheme` with the override of UI-091; its role values, and the status roles' base values, are those of `tokens.css`. |
| UI-140 | **matugen.** A user theme (UI-091) is CSS setting any `--omfp-*` role; matugen output (any scheme, light and dark) becomes one through the template in `contrib/matugen/` and shows with the theme `matugen` (UI-510, DMN-240), setting Synth's roles. Gradients, hover, selection, focus, diff and status colors derive (UI-135, UI-136), and the contrast guard fixes roles too faint to read (UI-196). |
| UI-196 | **Contrast guard.** Whenever the effective theme changes (load, user theme, `data-theme`, scheme), the app measures the roles used as text or marks on `surface` to `surface-container`: `primary`, `tertiary`, `secondary`, `error`, `on-surface-variant`, `--omfp-ok`, `--omfp-warn` need 4.5:1, `outline` 3:1, filled controls' labels 4.5:1 on their fills (the `VIEW` pill's among them), the `THREADS` pill 1.1:1 on the mode line. A failing role is set inline on `<html>`, moved in OKLab lightness just enough, hue kept, and named in `data-contrast-guard`. |
| UI-374 | **Native controls follow the scheme.** `tokens.css` MUST set `color-scheme` (`light dark` on `:root`, `light` or `dark` where `data-color-scheme` forces one), every color token that differs per scheme as `light-dark()`, and `accent-color: var(--omfp-primary)`, and no other stylesheet sets either, so native controls and scrollbars follow the scheme. An opened `<select>` list in WKWebView and WebKitGTK is a native menu the page cannot reach, hence the kit's `Select` (AGT-088). |
| UI-510 | **Built-in themes.** Besides Synth (UI-139, the default) omfp MUST ship `catppuccin`, `gruvbox`, `tokyo-night`, `nord`, `solarized`, `rose-pine`, the calm `graphite`, `paper`, `clay` and `primer` (UI-794), and `accent` (UI-512), chosen daemon-wide by `[ui] theme` (DMN-238; `:theme`, UI-513) and applied live as `<html data-theme>`, already in the served page. `matugen` shows the user theme over Synth (DMN-240). Each sets every role and status role for both schemes as `light-dark()` values in the token layer. |
| UI-511 | **The palettes** MUST map their official colors onto the roles (Catppuccin Latte / Mocha, Gruvbox, Tokyo Night Day / Night, Nord, Solarized, Rosé Pine Dawn / main, GitHub Primer); `graphite`, `paper` and `clay` are omfp's own calm neutrals with one restrained accent (cool gray and indigo; warm off-white and muted blue; ivory and terracotta). A color missing UI-196's thresholds on its own surfaces is moved in lightness, hue kept, so the guard overrides nothing in a built-in theme and item focus stays visible (UI-132). |
| UI-512 | **The system accent.** `accent` MUST derive every role but `error` and the status roles (Synth's) from the system accent color at fixed OKLab lightness (neutrals tinted by its hue, `primary` its hue, `tertiary` 60° further, `secondary` muted), so any accent passes UI-196 as it is. The macOS desktop window gives it as `<html>`'s inline `--omfp-system-accent` when it opens; without it (browsers, the Linux window) or without relative color syntax, `accent` shows Synth. |
| UI-514 | **Every theme in the gallery**: `/kit`'s `?theme=` MUST take every `[ui] theme` (`accent` from `?accent=#rrggbb`, default `#007aff`; `matugen` with the matugen fixture) and the Dux Solarized fixture, and its header picker links every theme, then both schemes, keeping the other parameters. The gallery checks (UI-174) run on each, `accent` with several macOS accents, and the guard overrides nothing but in the Dux preset. |

## Fonts and reading

| ID | Requirement |
| --- | --- |
| UI-141 | omfp **bundles** two families, latin subset, WOFF2, SIL OFL 1.1, served with the UI: **IBM Plex Serif** (prose) and **Commit Mono** (code, chrome, metadata), each at 400, 400 italic, 600 and 700, with their licence texts next to the font files; no other weight is bundled, so the kit uses only 400, 600 and 700 (UI-126). |

## Motion

| ID | Requirement |
| --- | --- |
| UI-145 | `[ui] motion` (`full` default, `reduced`, `none`; live, `:set motion=…`) sets `data-motion` on `<html>`, capped by `prefers-reduced-motion: reduce`, which acts as `none`. `reduced` keeps state indicators (spinners, indeterminate progress) and short feedback (entrances, color transitions) with a steady caret; `none` disables every animation and transition and scrolls instantly. ### Live voice

The live panel (UI-182) is a border box (UI-187) titled "Live voice" above the queue chips and the composer, its border
`error` after a failure and primary while focused. On top, the **spectrum**: 64 mirrored, log-spaced bars (70 Hz to
9 kHz), each showing the louder voice, the user's in a `tertiary` → `primary` gradient and the assistant's in `primary`
→ `tertiary` (UI-134), `outline` while muted, flat `outline-variant` when idle or failed; drawn from the role tokens and
only at motion `full`, a static meter otherwise. Then the latest line per role, one line each, or a failure's message
in `error`; last the status line: a `●` in the status's role, the status word, key chips (`spc mute`, `esc end`) or
`in another window (<client>)`, and the end and dismiss buttons. The composer's mic button shows pressed while a
session runs.
